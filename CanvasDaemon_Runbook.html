What CanvasDaemon does

CanvasDaemon turns Canvas course building into a controlled local workflow. Instead of copying HTML by hand, you pull course content, edit locally, preview inside real Canvas, and push only when ready.

Built for fast curriculum production without chaos.
Core idea

Local-first editing

Canvas pages and editable files are pulled into the project so Codex, VS Code, and local tools can edit them safely.

Safety layer

Dry-run by default

Most dangerous operations preview first. Real Canvas updates require explicit --apply.

Preview layer

Real Canvas render

Preview scripts write to a reusable CanvasDaemon Preview Page so you see Canvas-sanitized output before touching production pages.

North Star: AI can help edit locally, but CanvasDaemon decides what gets pushed, where it goes, and how it is backed up.

System architecture

The pipeline has five major lanes: Canvas pages, Canvas files/assets, quizzes, Panopto embeds, and previews. Reports and manifests act as the local source of truth.

Automation pipeline = local repo + Canvas API + reports.

Pull inventory

Scripts read Canvas and write local manifests/reports: pages, files, active module pages, quizzes, and Panopto references.

Edit locally

HTML pages, activities, quiz JSON, and assets live in project folders where AI coding tools can safely modify them.

Preview in Canvas

Preview scripts overwrite only the dedicated CanvasDaemon Preview Page. This tests what Canvas actually renders.

Push or sync

Production updates use explicit commands such as push_page.py --apply, push_module_page.py --apply, and quiz sync commands.

Script command center

Use the search box to filter scripts. These are the main capabilities currently in the pipeline.

test_canvas.py — connection check
Confirms .env values work and Canvas API is reachable. Safe read-only command.
Command
python scripts/test_canvas.py
pull_pages.py — pull Canvas pages
Downloads Canvas page bodies into pages/ and updates manifest.json. Used before editing locally.
list_pages.py — list pages from Canvas
Reads Canvas page list and prints titles/URLs. Good for quick inspection.
course_inventory.py — active vs unused page inventory
Reads modules and page manifest, then writes reports to reports/pages/.
find_page.py — find active module pages
Searches only pages currently used in modules. Best for production editing.
find_any_page.py — find active and unused pages
Searches all pulled pages and marks whether each result is active or unused.
push_page.py — push any page
Compares local HTML to Canvas, saves a pre-push backup, shows diff, and pushes only with --apply.
push_module_page.py — push active module page safely
Verifies the file appears in used_module_pages.csv, then delegates to push_page.py.
create_page.py — create Canvas page
Creates a new Canvas page from title/body file and updates local tracking.
add_page_to_module.py — add page to module
Adds an existing Canvas page to a module by page file/title/module name.
pull_files_metadata.py — pull Canvas file metadata
Creates asset_manifest.json and reports/files/canvas_files.csv.
find_asset.py — find Canvas assets and snippets
Searches Canvas file metadata and prints ready-to-copy iframe/img/link snippets.
download_referenced_editable_files.py — download referenced editable files
Scans active pages for Canvas file IDs and downloads editable HTML/CSS/JS/text files.
upload_canvas_file.py — upload new file asset
Uploads local assets into Canvas Files. Used for activities, images, and supporting files.
discover_panopto.py — discover Panopto embeds
Scans local pages for Panopto iframe/link references and writes Panopto reports.
create_classic_quiz.py — create Classic Quiz from JSON
Creates an unpublished Classic Quiz with multiple choice, true/false, multiple answers, fill blank, images, comments, time limit, and attempts.
pull_classic_quizzes.py — inventory Classic Quizzes
Pulls all Classic Quizzes into reports/quizzes/classic_quizzes_inventory.csv.
find_quiz.py — search quiz inventory
Searches quiz inventory by title, ID, type, published state, and URL.
sync_classic_quiz.py — sync quiz settings
Dry-run by default. Finds quiz by exact title and updates quiz shell/settings only with --apply.
setup_preview_environment.py — setup preview sandbox
Creates/reuses the permanent CanvasDaemon Preview Page and writes preview_config.json.
preview_page_in_canvas.py — Canvas-rendered page preview
Copies local page HTML into the dedicated preview page and opens Canvas.
preview_asset_in_canvas.py — Canvas-rendered asset preview
Uploads a local asset to the preview assets folder, embeds it on the preview page, and opens Canvas.

Pages pipeline

Pages are Canvas wiki pages. The key safety problem is duplicates: many pages have the same title, so active module checks matter.

Inventory first

course_inventory.py separates active pages from unused duplicates.

Find active file

Use find_page.py for module pages, not raw title guessing.

Preview in Canvas

Use preview_page_in_canvas.py to see Canvas-rendered HTML before production push.

Push with backup

push_page.py saves a pre-push backup and shows a diff. push_module_page.py adds active-page verification.

Assets and files

Assets include HTML activities, images, PDFs, videos, and other Canvas Files. Editable files can be downloaded and previewed before embedding.

Activities are first-class assets.

Metadata

pull_files_metadata.py records Canvas file IDs, URLs, content types, folders, and categories.

Search

find_asset.py outputs iframe/image/link snippets so assets can be embedded correctly.

Preview

preview_asset_in_canvas.py uploads a preview copy and embeds it in the Canvas preview page using Canvas-style file URLs.

Important: Created assets get pushed/uploaded to Canvas. Downloaded assets are local copies and do not update Canvas unless a future update-file/sync script is used.

Preview system

Preview is not just local browser rendering. It uses a real Canvas page so Canvas sanitization, iframes, file URLs, and embedded behavior can be tested safely.

Preview inside Canvas before production push.

Setup

setup_preview_environment.py creates/reuses CanvasDaemon Preview Page and writes preview_config.json.

Page preview

preview_page_in_canvas.py copies local page HTML into the preview page.

Asset preview

preview_asset_in_canvas.py uploads the local asset to preview assets and embeds only the iframe/image/link part.

The preview page is reusable. Running a new preview overwrites the previous preview, keeping Canvas clean.

Panopto videos

Panopto videos are external embeds, not Canvas Files. CanvasDaemon discovers them from local page HTML.

Discovery

discover_panopto.py scans pages for Panopto iframe and link URLs, then writes panopto_manifest.json and a CSV report.

Future path

Later, Panopto can become a first-class asset source with find_panopto.py and direct API pull if credentials become available.

Safety rules

CanvasDaemon is designed around reversible changes and explicit deploy commands.

Do

Run inventory before editing
Use find_page.py for active pages
Preview in Canvas before push
Use dry runs first
Commit after stable milestones

Do not

Blindly edit duplicate page names
Push without previewing important HTML
Bulk-update quizzes without explicit IDs
Commit .env or Canvas tokens
Assume local browser preview equals Canvas rendering
Rule: Discovery scripts never delete. Push/update scripts require explicit intent.
