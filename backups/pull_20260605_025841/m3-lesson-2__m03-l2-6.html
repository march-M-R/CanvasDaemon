The Core Question

Most projects fail before they train. Yours will not.

Three things make or break the training day: the problem you chose, the balance of your samples, and whether you saved the model. Get those three right and the rest of the week becomes easier.

The Problem Test

A good two-class problem passes all three.

Before you open Teachable Machine, run your idea through these three checks. If it fails any one, pick a different problem.

1

Visually different

Distinct

A stranger looking at five random samples from each class could sort them correctly with no training.
2

Data you can collect

Capturable

You can take 30 varied photos of each class today, with the phone in your pocket and the environment you live in.
3

Worth doing

Useful

Name one real person who benefits when the model gets it right. Specific person, specific benefit.

Key Point

If you cannot name a real person who benefits from a correct prediction, you have picked an academic exercise, not a project. Pick again.

Balanced vs Imbalanced Classes What happens when one class outnumbers the other.

Same model, same algorithm, same trainer. The only difference is how many samples each class has. The outcomes are not similar.

Compare on Balanced: ~30 / ~30 Imbalanced: 60 / 10
Example Class A: 30 samples Class A: 60 samples
Outcome Class B: 30 samples Class B: 10 samples
Note Model must actually distinguish them. Model learns 'guess A always'.
Why it matters The model has no shortcut available. It has to learn what makes the two classes different from each other. Accuracy reflects skill, not bias. The model discovers that 'always predict Class A' is correct 86% of the time. That looks like a good model on the dashboard. It is a model that has learned nothing about Class B.

The Four Save-Point Habits Open this section to see the four moments where saving matters.

Save Discipline

Save four times, lose nothing.

Every senior ML engineer has lost a model at least once. The senior ones developed habits. Borrow theirs.

1

Habit 1

Save the model file the moment training finishes

Before you celebrate. Before you test more. Before anything else.
2

Habit 2

Name the file specifically

'avocado_ripeness_v1.zip' beats 'tm-export-2024.zip'. Future-you needs to find this.
3

Habit 3

Record the path in your portfolio notes

If you cannot find the file in 30 seconds two days from now, you did not save it. You hid it.
4

Habit 4

Take a screenshot of the training summary

The per-class accuracy is metadata you will want when writing the Model Card.

Result

Four small actions, taken in the right order, turn a fragile session into a finished deliverable. Skip any one and the next day starts with a 'where did it go' email.

Common Setup and Training Mistakes Open this section to review the traps.

Common beliefs that fall apart on contact with real data.

Myth

Only one class has variety

Reality

Class A photos are taken in 5 locations. Class B is taken at one desk. The model now classifies 'where the photo was taken,' not the subject. Vary both classes.

Myth

Training data and test data are the same

Reality

Using the same photos to train and to test gives you 100% accuracy and zero information. Set aside fresh samples for testing on Day 3 before you train.

Myth

'It worked in the demo'

Reality

A model that recognizes your hand holding the object will fail when shown the object alone. The training condition becomes the model's only world.

Key Takeaways

What you should remember from Lesson 2

The problem comes first. A strong two-class pair is Distinct, Capturable, and Useful. Skip any one of those and the rest of the week fights you.

Balance and variety beat raw volume. Thirty varied samples per class outperform a hundred near-duplicates.

Save immediately after training. The model lives only in your browser tab. Close it before saving and the entire day's work is gone.
