The Core Question

Accuracy on the training data tells you nothing.

Every model scores high on the data it was trained on. The only test that matters is the one run on samples the model has never seen. This is the day you find out whether your model learned the subject or learned the photo conditions.

Animation of analyzing predictions on a chart

Honest Testing Defined

Running the model on at least ten fresh samples per class that were not part of training, and logging every prediction.

The Four Outcomes of Every Prediction Click to expand or collapse this section.

Every prediction lands in one of four boxes

Right vs Wrong is not enough. Wrong has flavors.

When a binary classifier returns a label, the prediction is either correct or incorrect, and in two different ways each. The four cells are the entire vocabulary of model evaluation.

1

Said yes, was right

True Positive

The model called it Class A, and it was Class A. Move on.
2

Said no, missed it

False Negative

The model called it Class B, but it was actually Class A. The most expensive error in safety contexts.
3

Said yes, was wrong

False Positive

The model raised an alarm that wasn't justified. The most expensive error in customer contexts.

Key Point

The cost of a false negative and the cost of a false positive are almost never the same. Knowing which one your project hates more is the start of real model design.

Training Accuracy vs Test Accuracy Two numbers that look the same and mean nothing alike.

When someone tells you a model is 95% accurate, the first question to ask is: accurate on what? The answer separates a working model from a press release.

Compare on Training Accuracy Test Accuracy
Example Test set: data from training Test set: fresh, unseen samples
Outcome Typical score: 95-100% Typical score: highly variable
Note Often meaningless. The only meaningful number.
Why it matters The model literally memorized these samples. Scoring high here proves the model can remember. It says nothing about whether the model can generalize to anything new. These samples were never part of training. If the model scores high here, it has learned something that generalizes. If it scores low here while training was high, the model only memorized.
The Confusion Matrix in Plain English Open this to see how to read the matrix on first glance.

Two by Two

Rows are truth. Columns are what the model said.

The confusion matrix is the single most useful tool in model evaluation, and it is just a four-cell grid.

Reading the Matrix

Diagonal cells are correct predictions. Off-diagonal cells are mistakes. The biggest off-diagonal cell is your weakest spot.

Step 1

Truth → Rows

Each row represents the actual class of the test samples. Two rows for a binary classifier.

 →

Step 2

Top-left: True Positive

Actual A, predicted A. Correct prediction for Class A.

Step 3

Diagonal cells = Right

When the row label matches the column label, the model got it right.

Step 4

Off-diagonal = Wrong

Whichever off-diagonal cell has more samples is exactly the kind of mistake the model makes most often.

Rows

True class of the sample.

Columns

What the model returned.

Diagonal

Predictions that match reality.

Off-diagonal

Your debugging target.

Four Questions to Interrogate Every Model Open to see the questions before you accept any accuracy claim.

Model Interrogation

Four questions. One per mistake.

Before you ship a model, ask it these four questions. If you cannot answer them with specific numbers from your test log, you do not actually know how the model behaves.

1

Q1

What is its test accuracy on fresh data?

Training accuracy is not the answer. Use samples the model has never seen.
2

Q2

Which class does it confuse most?

Look at the off-diagonal cell with the higher count in your confusion matrix.
3

Q3

Is it confident when wrong?

Sort predictions by confidence. The confident-and-wrong cases are the dangerous ones.
4

Q4

What conditions break it?

Test under conditions you did not train on. Find the failure mode before users do.

Result

A model that answers all four with specifics is a model you can describe in a Model Card. A model that cannot is a model that is hiding something.

Common Testing Mistakes Open this section to review the traps.

Common beliefs that fall apart on contact with real data.

Myth

Counting only wins

Reality

Logging only the predictions you wanted to see is not testing. Log every prediction, including the boring correct ones, including the embarrassing wrong ones.

Myth

Testing one sample at a time

Reality

Two correct predictions in a row does not mean 100% accuracy. Run at least 20 test predictions before reading the matrix.

Myth

Trusting high confidence

Reality

A model that is 99% confident and wrong is the most dangerous kind. High confidence often signals the model is being fooled by a pattern it shouldn't trust.

Key Takeaways

What you should remember from Lesson 3

Test on samples the model never saw. Anything else is theater. Ten fresh samples per class is the minimum to claim anything.

Read the confusion matrix. The diagonal is correct. The off-diagonal cells tell you exactly which class the model confuses with which.

Confidence is not correctness. A 99% confident wrong answer is a different problem from a 60% confident right answer. Log both.
