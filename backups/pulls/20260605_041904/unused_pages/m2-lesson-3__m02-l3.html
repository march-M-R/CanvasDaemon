The Core Question

The only honest test is one the model has never seen.

Every model scores high on its own training data. That score is almost worthless. The number that matters is on samples held out from training, evaluated only once. Everything in this lesson is about preserving that one honest measurement.

Animation of testing predictions against ground truth

Honest Testing Defined

Evaluating a model on data it has never seen, never been tuned on, and never been peeked at by the team.

Three Sets, Three Jobs Click to expand or collapse this section.

Train, validation, test

Each set does exactly one thing.

A clean ML project splits its data into three sets, each used for one job. Mix the jobs and you lose the ability to know whether your model actually works.

Used for learning

Training set

The model adjusts its weights on these examples. Typically 60 to 80 percent of the data.

Used for choosing

Validation set

Compare two model versions, pick hyperparameters, decide when to stop training. Typically 10 to 20 percent.

Used for reporting

Test set

The final honest number. Touched exactly once at the end. Never tuned on. Typically 10 to 20 percent.

Key Point: Every time you peek at the test set to make a decision, it becomes a second validation set. The number it produces is no longer 'honest.' Hold one set for the very end and never touch it.

Memorize vs Learn Two patterns, two completely different stories.

When training accuracy is much higher than test accuracy, the model memorized. When they match, the model learned. Reading those two numbers together is the single most useful diagnostic in ML.

Memorized (overfit)

Training accuracy

99 percent

Test accuracy: 60 percent.

The model rote-learned the training examples. On any new input, it has no real understanding to fall back on. The accuracy gap is the alarm bell. The cure is more data, regularization, or a simpler model.

Learned (generalizes)

Training accuracy

88 percent

Test accuracy: 86 percent.

Slightly lower on training, almost as high on test. The model captured a pattern that survives to fresh inputs. This is what production-quality ML looks like. Boring is good.

Where Leakage Hides

Three kinds of leakage. All make accuracy lie.

Data leakage means the model has access during training to information it would not have at prediction time. The result is a test score that looks perfect and a production model that fails.

Three Common Leakage Patterns

Every one of these has caused famous, expensive failures. They are easy to overlook because the accuracy numbers look great until you ship.

Future leakage

A feature was recorded after the outcome. The model 'predicts' something it already knows.

Target leakage

The label or a near-duplicate of it ends up as an input. The model has the answer in the question.

Train-test contamination

Some training examples sneak into the test set. The model has 'seen' part of the test.

Preprocessing leakage

Scaling or normalization uses statistics from the test set. Training implicitly knows about the test data.

Future: A feature recorded after the answer.

Target: The label is hiding in the inputs.

Contamination: Test examples leaked into training.

Preprocessing: Stats computed on the wrong set.

Four Questions to Interrogate Every Train/Test Setup Open this to see what to check before you trust any accuracy claim.

Train/Test Integrity

Four questions. One per leak.

Before you accept any test score, run the setup through these four questions. If any answer is unclear, the score is not yet honest.

Q1

How was the data split into train and test?

Random? By time? By user? The wrong split for the wrong problem ruins the test.

Q2

Is every feature available at prediction time?

Anything recorded after the outcome is a leak. Anything that comes from outside the training data is suspect.

Q3

Were any rows duplicated across train and test?

Look at the IDs. Look for near-duplicates. Time-series data is especially vulnerable here.

Q4

Did any preprocessing step use the test set?

Scaling, encoding, normalization. Each one needs to be computed on training data only.

Result: Four answers, four short sentences. Together they take five minutes to write. They are the difference between an accuracy number you can defend and one that quietly breaks the moment the model ships.

Common Training and Testing Mistakes Open this section to review the traps.

'I trained on everything for better accuracy'

If you train on everything, you have no honest way to know the model works. The test score is meaningless because there is no test set.

'I improved the model 12 times by checking the test set'

Every check on the test set is a small leak. By the 12th iteration, your 'test score' is really a second validation score. Hold one fresh set for the very end.

'Random split is always safe'

For time series, a random split lets future information leak into training. For user data, random split means the same user appears in both. Pick a split method that matches the prediction setting.

Key Takeaways

What you should remember from Lesson 3

Training accuracy is not the answer. Test accuracy on fresh, held-out data is what tells you whether the model generalizes.

Three sets, three jobs. Train, validation, test. Mixing the jobs is how good projects quietly fail.

Data leakage is the most expensive bug in ML. A feature that includes the answer makes the model look perfect and useless at the same time.
