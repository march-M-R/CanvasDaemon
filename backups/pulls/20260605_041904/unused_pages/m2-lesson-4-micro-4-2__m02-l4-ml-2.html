When Bias Enters Through the Training Data

Bias has five entry points. Find which one fed your model.

Big Question

“If the algorithm is 'just math,' how does it learn discrimination?”

Concept Companion

Five places to audit.

Bias can only enter at five specific places in the data pipeline. Knowing where each one lives is the first step in any honest audit.

1

Who got measured

Collection

Whose data made it into the dataset. Anyone left out is invisible to the model.

2

Who decided the answer

Labels

Labeler bias becomes label bias becomes model bias. Speed pressure and vague guidelines amplify it.

3

Which rows were used

Sampling

If you trained on data from one region, the model is for that region only.

Key Insight

The math is honest. The data is not.

Algorithms do exactly what their training data tells them to do. If the training data reflects historical bias, the model reproduces that bias at machine speed. The bias does not enter through the math. It enters through choices made before any code ran.

Compare

Where bias entered, in real cases.

Same kind of harm, very different entry points in the pipeline. The fix is different depending on where it entered.

Case

Recidivism prediction model

Entry point

Collection (arrest data reflects who got policed)

Fix

Audit data; consider different label source

Case

Resume hiring AI

Entry point

Labels (past hiring decisions were biased)

Fix

Re-label or remove the historical labels

Case

Medical model failing in a new region

Entry point

Sampling (trained at one hospital)

Fix

Retrain with more representative samples

Case

Chatbot that turned offensive

Entry point

Deployment (learned from hostile user input)

Fix

Filter inputs; freeze learning during deployment
