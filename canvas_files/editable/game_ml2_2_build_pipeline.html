Scenario 1 of 5 · Sentiment Analysis

A sentiment analysis model was trained on product reviews from a single electronics retailer. When deployed to analyse restaurant reviews, it consistently labels complaints as positive and praise as negative.

Error: The model performs well on electronics reviews but fails completely on any other category of text.

Which pipeline step caused this failure?

Correct
The training data came from a single narrow source and did not represent the real use case. Restaurant and electronics reviews use different language, vocabulary, and tone. The model learned patterns from electronics text and those patterns simply do not transfer. This is a data collection failure: the wrong data was gathered for the intended application.
Not quite
Feature extraction processes whatever data it receives. The problem is upstream: the training data itself was not representative of the real use case. Even perfect feature extraction from the wrong data would produce a model that fails on different domains. The failure is in data collection, before feature extraction runs.
Not quite
Training ran correctly on the data it was given. The problem is that the data did not represent the actual task. Even perfectly executed training on narrow data produces a model that only works on that narrow slice. The failure originates in data collection, not training.
Not quite
The model was deployed correctly to a new task. The failure existed long before deployment, in how the training data was collected. Deployment cannot fix a model trained on the wrong data. The root cause is upstream in data collection.

Scenario 2 of 5 · House Price Prediction

A house price prediction model was given raw address strings as its only input. The model performs no better than random guessing and cannot identify any pricing patterns.

Error: The model received data but could not learn anything meaningful from it.

Which pipeline step caused this failure?

Not quite
Data was collected. Addresses do contain location information relevant to house prices. The problem is that raw address text was never converted into usable numerical or categorical signals. That conversion should happen in feature extraction. The failure is in the step after collection.
Correct
Raw address text like "14 Oak Street, Brooklyn" contains no signal a model can learn from directly. Feature extraction should have converted addresses into meaningful variables: neighbourhood, proximity to transit, school ratings, square footage, number of bedrooms. Without extracting actual features, the model receives meaningless text and has nothing to learn from. This is a feature extraction failure.
Not quite
Training ran correctly on the inputs it received. The problem is that the inputs were meaningless strings with no predictive signal. Training cannot extract pricing patterns from raw text. The failure is in feature extraction, which runs before training and determines what the model is actually given to learn from.
Not quite
Evaluation tests the model after training. The failure happened before evaluation, in feature extraction. The model never had a chance to learn anything because it received meaningless inputs. Better evaluation would reveal the problem but would not fix its cause.

Scenario 3 of 5 · Fraud Detection

A fraud detection model achieves 99.7% accuracy in testing. When deployed, it consistently flags the same type of transaction every time, completely missing different fraud patterns that did not appear in training.

Error: The model memorised training examples instead of learning generalisable patterns.

Which pipeline step caused this failure?

Partially correct
The training data lacked diversity of fraud types, which contributed to the problem. But the more specific failure is in training: the model overfitted, memorising the specific examples it saw rather than learning the underlying patterns of fraudulent behaviour. Both play a role, but overfitting during training is the proximate cause.
Not quite
Feature extraction was likely fine. The model received meaningful transaction data. The issue is that during training, the algorithm learned the specific examples too closely rather than the general patterns behind them. This is a training failure called overfitting, not a feature extraction problem.
Correct
This is overfitting: a training failure where the model memorises the training data instead of learning generalisable patterns. It achieves near-perfect accuracy on data it has already seen but fails on anything new. Solutions include regularisation techniques, dropout, using more diverse training data, and proper cross-validation during the training process itself.
Partially correct
Better evaluation using diverse test cases, including fraud types not in training, would have caught this problem before deployment. But the root cause is that training produced an overfitted model. Evaluation can detect the failure; the training step is where it originated.

Scenario 4 of 5 · Medical Imaging

A medical imaging AI achieves 98% accuracy in evaluation. When deployed, doctors notice it flags a specific region in the lower-right corner of every scan, including blank control scans with no patient data.

Error: The model learned a spurious pattern completely unrelated to the actual medical condition it was supposed to detect.

Which pipeline step caused this failure?

Correct
The training images likely contained a consistent artifact in the lower-right corner, such as a scanner watermark, equipment marking, or hospital logo. This artifact correlated with positive diagnoses because it appeared consistently on images from the same scanner that produced positive results. The model learned to flag the artifact rather than the actual condition. Contaminated training data with a systematic flaw is a data collection failure.
Not quite
Feature extraction faithfully processed what was in the images. The artifact was present in the raw training data before feature extraction ran. The root cause is that the training images themselves were contaminated with a systematic flaw. Feature extraction cannot be blamed for accurately representing what was in the data it received.
Partially correct
Better evaluation on diverse scanners and blank control scans would have exposed this problem before deployment. But the root cause is that the training data contained a contaminating artifact. Evaluation can reveal the failure; data collection is where it was introduced.
Not quite
Training learned exactly what it was shown: the artifact in the lower-right corner correlated with diagnoses in the training data, so the model learned to use it. The training algorithm is not at fault. It correctly identified the strongest pattern in the data. The problem is that the data itself contained a spurious artifact. That is a data collection failure.

Scenario 5 of 5 · Loan Approval

A loan approval model was developed, trained, and evaluated internally. After deployment, an audit finds it approves loans for applicants from wealthy zip codes at a rate 40% higher than for applicants with equivalent financial profiles from lower-income areas.

Error: The model produces systematically different outcomes for groups that should be treated equally based on their financial situation.

Which pipeline step caused this failure?

Correct
Historical lending data reflects decades of unequal access to credit. If the training data shows higher approval rates for applicants from wealthy areas because of past discriminatory lending practices, the model learns and reproduces those patterns as if they are legitimate. The model did not invent this bias. It learned it from the patterns encoded in the historical data it was trained on. This is a data collection failure: the training data carried historical discrimination forward into a new system.
Partially correct
Training amplified the patterns present in the data. But those patterns themselves came from the data collection step. The training algorithm did exactly what it was supposed to do: it learned from the data it was given. Biased input data produces a biased model. The root cause is in what data was collected and used, not in how training ran.
Partially correct
Evaluation should have included fairness metrics across demographic groups. If it had, this disparity might have been caught before deployment. But the bias originated in the training data, not in evaluation. Evaluation can detect it; data collection is where it was introduced into the system.
Not quite
Deployment worked exactly as designed. The model was applied correctly. The problem was baked into the model before deployment, during data collection and training. Deployment did not create the bias; it exposed a wider audience to a bias that already existed in the model.

All five failures diagnosed.

Every AI failure traces back to a specific pipeline step. Data collection introduces bias. Feature extraction determines what the model can see. Training determines what it learns. Evaluation reveals whether it generalises. Knowing the step is the first step to fixing it.
