▾Three Tests for Whether Something Is Data Click to expand or collapse this section.

Recorded, comparable, machine-readable

Three checks. All three matter.

Not everything you observe is data. To qualify, it has to pass three tests. Skip any one and the machine has nothing to learn from.

1

Captured outside your head

Recorded

A measurement, an observation, or a signal saved in a file. A feeling becomes data only after it is written down.
2

Same format as the other examples

Comparable

Every row should have the same columns, every photo should be loadable in the same way, every audio file the same kind of waveform.
3

Loadable as numbers, text, or pixels

Machine-readable

A handwritten note is data only after it is transcribed. A scribbled drawing is data only after it is photographed.

Key Point

If you cannot show the data to a stranger and have them load it the same way you did, it is not yet usable for a model.

▾Inputs vs Outputs in a Recommender Every AI feature is a function. Inputs go in. Outputs come out.

When an app feels magical, the magic is almost always a recommender. Strip away the marketing and you find the same shape: structured inputs in, ranked outputs back.

Compare on Inputs (what goes in) Outputs (what comes out)
Example Example: streaming music Example: streaming music
Outcome Listening history, song features, time, device A ranked list of recommended songs
Note Captured continuously, every interaction. Updated as new interactions or context become available.
Why it matters Every input is something the app already collected. Behavioral history (what you played), item features (genre, tempo), context (time of day, location). The mix is what the model uses to predict. Outputs are usually ranked candidates, not single answers. The app picks the top few to show. The model exists to make the next few options feel relevant to you.
▾Structured vs Unstructured Data Open this to see the two big shapes data takes.

Three Common Data Structures

Most real-world data is somewhere in between.

Structured, semi-structured, and unstructured are parallel categories. The category describes organization; it does not determine data quality or model readiness.

All Data You Will Encounter

On any given project, your data is almost never pure structured or pure unstructured. The bulk of the work is moving messy data toward something usable.

Data category

Structured

Organized using a defined schema, such as a database table. It may still require validation and cleaning before modeling.

Data category

Semi-structured

Uses organizational markers without a fixed table structure, such as JSON or XML.

Data category

Unstructured

Does not follow a predefined data model, such as free-form text, images, audio, or video.

Preparation is a separate question

Any data type may require cleaning, validation, transformation, or labeling before it is suitable for a model.

▾The Four Data-Source Questions Open this to see the questions every analyst asks before they trust a dataset.

Data Provenance

Before you trust the data, interrogate it.

Every dataset has a history. The history shapes what the model can and cannot learn. These four questions are the start of every honest project.

The full collection of examples is the dataset. Each useful input characteristic is a feature, while the answer attached to a training example is its label.

1

Q1

Where did this data come from?

Identify who collected it, which tool they used, and when they collected it. If you cannot answer, you cannot defend any conclusion drawn from it.
2

Q2

Why was it collected?

Data collected for a different purpose almost always has the wrong shape for yours. The original intent leaks in.
3

Q3

What was left out?

Every dataset has gaps. The model will not know about anything that is not represented. Name the gaps before you train.
4

Q4

Who is in the data, and who is not?

Demographics of the people, places, and conditions in the data. Anyone missing is invisible to the model.

Result

Four questions, four short answers. They take ten minutes. They are the difference between a model you can defend and a model you have to apologize for later.

▾Common Beginner Mistakes About Data Open this section to review the traps.

Common beliefs that fall apart on contact with real data.

Myth

'Anything online is fair to use'

Reality

Public does not mean ethical. Public does not mean accurate. Public does not mean labeled. Every dataset needs a real review before training, including the ones found in tutorials.

Myth

'More data fixes any problem'

Reality

Bad data scales bad outcomes. Doubling your training set when the labels are wrong gives you a model that is more confidently wrong. Volume only helps if quality is already there.

Myth

'The model knows what to ignore'

Reality

Models cannot tell which columns to ignore unless you remove them or weight them down. Including irrelevant features is not free; it adds noise and risk.

Key Takeaways

What you should remember from Lesson 1

Data is what gets recorded. A feeling, a guess, or a conversation is not data until it is captured in a form a machine can read.

Every AI system has inputs and outputs. Knowing what goes in and what comes out is the start of understanding any model, no matter how impressive it sounds.

Structured data fits in rows and columns. Unstructured data does not. Most data in the real world is messy, and the cleanup work is real work.
